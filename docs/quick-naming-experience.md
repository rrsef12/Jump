# 快速命名深化方案：把一次命名变成可连续工作的过程

> 历史设计文档：旧标签与分组系统已于 2026-10-19 删除，当前操作与检查以 README 和交付说明为准。

2026-10-18 · 产品提案与交互研究，尚未接入原生程序。

后续原生实现见 [交付说明](quick-naming-delivery.md)；本文保留设计过程与进一步扩展设想，不代表所有设想均已实现。

延续已认可的字段式方案。核心目标进一步收敛为：**原有信息能可靠沿用，本次变化能直接操作，结果能在保存前看明白。**

## 1. 重新定义用户任务

用户通常不是“组装一个字符串”，而是在做以下工作：

| 真实任务 | 应沿用什么 | 应变化什么 | 推荐入口 |
| --- | --- | --- | --- |
| 同一文件继续迭代 | 项目、主体、类型、变体、当前阶段、目标位置 | 按实际目录重新计算版本 | 续存版本 |
| 同一资产探索另一版设计 | 项目、主体、类型、阶段、目标位置 | 明确选择变体；新名称范围重算版本 | 派生变体 |
| 开始另一个资产 | 项目、方案结构和通用类型 | 主体；不合适的资产专属值需提示处理 | 更换主体字段 |
| 准备交付 | 项目、主体、类型、已有变体 | 显式应用交付方案的阶段、位置、规则 | 交付方案 |
| 临时破例命名 | 当前内容和原结构快照 | 本次完整名称 | 编辑完整名称 |

这些入口操作同一套字段状态，没有三套互不相通的命名引擎。“续存版本”也不是每点一次就把预览数字加一：相同目录状态下重复点击应得到相同候选号码。

三个任务入口属于对应方案可配置的快捷动作。初始只露出当前相关、用户固定的动作，不把所有功能铺满主面板。

## 2. 七项真正有价值的深化

### A. 连续工作：记住“结构”，而不只记住最后一串文字

已有保存记录只有路径、程序、核验时间，不能直接恢复命名结构。新增的是与具体成功写入关联的命名快照，包括方案版本、字段值、来源和编号策略。

再次保存同一文件时，可以从可靠来源恢复字段，直接展示下一版本。可靠来源依次为：本次窗口已有结构；已核验且匹配实际目标的命名快照；用户选定模板的唯一解析结果。只知道窗口标题或上次在同一软件保存过，不足以自动沿用。

同一软件中的两个文档、两个保存窗口各有自己的草稿。切回窗口继续此前编辑；窗口关闭后不把临时草稿冒充成功记录。跨重启恢复工作状态作为后续可选功能，首版只做进程内、身份可核验的窗口会话隔离。

最常见的续存任务应做到：当前方案已应用、目录能力正常时，用户无需重新选择资产与类型，核对后走原有保存流程。

### B. 直接编辑结果里的片段

字段卡片和最终名称之间建立映射。点最终名称里的“守卫”，打开主体候选；点“工作”，改阶段；点“v013”，查看编号规则和依据。

推荐默认保留字段卡片，因为字段含义清楚。提供可选紧凑显示：直接用名称片段作为编辑入口，省掉重复的一组卡片。两种显示共用状态、历史和规则，不能成为两个功能版本。

如果替换规则跨多个字段改变了文字，片段映射可能不再唯一。这时只展示经过变换的最终文本，并提供“编辑来源字段/替换规则”；不能点一个模糊区间就猜着改某个字段。

长名称允许自然换行/展开。完整扩展名持续可见，不能为了紧凑把最重要的结尾藏掉。

### C. 用一个已有文件名建立方案

首次使用最大的阻力可能是“我还得先搭好模板”。增加按实例建立方案：

1. 用户粘贴一个名称，例如 `Harbor_Guard_Model_Work_v012.blend`。
2. Jump 提出拆分建议；用户给每段指定项目、主体、类型、阶段、版本或固定文字。重复分隔符、字段内下划线和多个数字段都允许手工调整边界。
3. 可再提供第二个例子，帮助区分固定文字与变化字段；只有一个例子时不假装已经可靠归纳出规范。
4. 实时展示一个新名称，用户确认后另存为自己的方案。

项目文字、数字和英文缩写只作建议，不能直接变成自动规则。`LOD0`、`1001`、`4K`、日期和版本必须分别识别；无法区分时要求用户指定这个字段的含义。

此能力优先于新增更多示例预设：它让用户把已有习惯带进 Jump。

### D. 字段具有清晰的来源与继承范围

字段值不仅有 value，还应知道来自哪里：项目继承、方案默认、现有名称、当前输入，或自动计算。正常状态只在字段编辑面板展示来源，主面板不堆图标。

| 信息 | 默认范围 | 换主体时 | 换项目时 |
| --- | --- | --- | --- |
| 项目前缀/作者 | 当前项目或方案显式设定 | 保留 | 更新继承值 |
| 主体 | 当前资产或本次会话 | 替换 | 不自动带入新项目 |
| 类型/阶段 | 当前方案、本次会话 | 通常保留 | 按新方案核对 |
| 变体/资产专属备注 | 当前资产、本次会话 | 提示保留或清除，不静默移植 | 不自动继承 |
| 日期/版本 | 当前目标、当前求值上下文 | 重新计算 | 重新计算 |

用户临时覆盖项目继承值后，显示“本次自定义”，并可一键恢复继承。切换方案时按稳定字段 ID 迁移兼容值；无法迁移的临时内容先显示差异并保留撤销点。

首版不增加复杂“锁定所有字段”系统。先让继承、自定义和恢复来源可理解，再决定是否需要高级锁定。

### E. 本次变化可见，错误就在发生的地方修

展示一条简洁变化摘要，例如：

- `版本 v012 → v013`
- `新增变体 夜巡 · 版本按新名称计算`
- `阶段 工作 → 交付 · 位置 work → delivery`

摘要基于会话开始的真实目标与当前待应用目标比较，不基于静态示例或上次点击。用户原窗口手工改名时更新外部基线，旧异步结果失效。

名称与路径分别核对：只更改阶段字段，不自动跳目录；选择带路径的交付方案才进行目录变更。界面要显示目标路径和格式；真实应用格式未改变时不能把 .blend 显示成 .fbx。

错误给出当前可执行的动作：缺主体则直接编辑主体；目录未知则选择目录；版本冲突则复核并显示新候选。轻微提示就地呈现，覆盖/提交边界沿用原软件确认。

“撤销命名”只撤回命名；若方案同时切过目录，要明确显示位置尚未回退，并单独提供经过身份校验的恢复位置动作。不能把外部窗口中的多步操作承诺成原子事务。

### F. 中文操作，规范名称输出

复用现有 `Preset.name / value / keywords` 的显示名与输出值概念。候选可显示“守卫”，实际输出 `Guard`；搜索“守卫 / guard / 角色”都能命中同一项。

映射由用户定义、方案选择，临时词默认原样输出。不要自动翻译固有名词，也不要同时维护互不关联的中文库与英文库。

扩展到 Blender、Houdini、SD 时，复用明确选择的项目与资产字段，各应用使用自己的输出结构。例如同一 Guard 可以出现在工作文件、模型导出、贴图命名中；字段复用不代表 Jump 已获得跨应用导出能力。

这是一种轻量的命名一致性，不建设资产数据库，也不扫描整个磁盘寻找关联文件。

### G. 熟练操作更快，鼠标操作仍完整

- 面板内设置局部“搜索字段/候选”入口；可选快捷键只在 Jump 有焦点时生效。
- 输入候选名、方向键选择、Enter 应用字段，Esc 放弃该字段未提交的输入；不需要回到管理页。
- 中文输入法正在组词时，Enter 只确认输入法，不填入、不保存。
- 候选面板中的 Enter 只提交这一字段，不能同时触发保存；必须经过另一个明确的保存操作。
- Ctrl+Z 在输入框中继续撤销文字；离开文字编辑后，单独入口撤销组合。
- 固定候选保持位置；搜索结果可以排序，编辑期间不能在指针下重新排列。
- 跟随原软件弹出时仍不抢焦点。用户显式进入命名区之后才操作键盘。

## 3. 更简洁的默认面板

上版的六字段网格适合展示概念，但正式产品不必每天展示日期、备注和高级规则。

推荐布局：

1. 项目与当前方案；现有位置区保留。
2. 一到三个与方案有关的常用动作。
3. 最多四到六个当前常用字段，候选面板按需出现。
4. 持续可见的完整结果、格式与必要的目标位置。
5. 一条本次变化摘要；底部继续使用现有能力对应的填入/保存操作。

版本放在结果旁直接操作，日期和备注未启用时收进“更多字段”；已启用的内容必须有可见提示，避免收起后忘记规则仍在生效。

交互示意提供“字段面板”和“名称直改”两种显示供比较。推荐前者作为默认，后者作为熟练用户选项。它们仅用于验证命名区交互，没有复制原生窗口全部位置栏和保存控件。

## 4. 必须解决的底层问题

### 结构化求值，不靠重新拆字符串维护状态

建议使用一个纯求值过程：

`上下文 + 字段结构 + 当前值 + 规则 → 名称 + 可追溯片段 + 问题 + 编号请求`

片段保留 fieldId 与值来源；带跨段替换时可以标记映射不唯一。最终字符串用于回填，不反过来成为每次编辑的唯一状态。

编号与目录 I/O 继续由已有后台工作器执行。新请求的 key 必须覆盖目标窗口会话、项目、方案版本、字段值、目录、格式和规则。任何一个变化都让旧结果失效。

### 草稿、填入、提交、核验分开

- 字段输入中的内容是草稿；非法或未提交内容不写入目标输入框。
- 点候选/确认字段，生成一次可撤销的命名修改，按现有通路回填。
- 保存前复核真实目标和编号；无法确认时保留可编辑状态。
- 原软件收到保存操作，只能说已提交。
- 已有元数据核验成功后，才产生成功记录与成功使用记忆。

候选点击不应为了“预览”再多出一个确认步骤；确认的是自由输入或有明显外部副作用的复合方案。变更仍应立刻反馈。

### 保存快照必须跟随那次保存请求

`SavedFile` 目前只有 path/process/verifiedAt。若加入结构恢复，必须在回填/提交或观察到原软件保存目标时冻结对应的 NamingSnapshot，并与 SaveProbe、窗口会话和目标版本关联。

异步核验可能在用户切到另一个文件后才成功。绝不能在成功回调时读取当前 `g->parts` 来补记上一次文件的结构。外部手动改名造成结构无法对应时，只记实际路径，不附会旧字段。

### 继承和历史不能污染全局配置

项目默认、方案默认、本次覆盖、最近成功使用应分别保存。取消输入不写配置；临时输入只进入会话；“加入库”“修改默认值”“保存方案”是明确动作。

记录方案版本，避免用户修改模板后，旧保存记录被新版模板错误解释。旧配置保留自由组合行为；升级前备份，失败不覆盖。

## 5. 性能与可靠性目标

以下是拟定验收目标，不是当前实测成绩：

- 普通字段选择的本地视觉反馈尽量在 50 ms 内出现；本地纯命名不能等待目录 I/O。
- 候选过滤在约 1,000 条本地标签规模下目标 100 ms 内完成，以真实中文/关键词数据测量 P95。
- 版本检查显示计算中并可继续改字段；网络目录不设无法兑现的“保证两秒完成”。
- 后台结果不覆盖新输入；同名目录中不同扩展名、日期、LOD、UDIM 样式数字不得混算。
- 字段编辑、中文输入法、焦点恢复与两种布局的键盘可达性作为正式验收项。
- 配置往返、同文字不同字段、无效路径、版本冲突、外部改名、多窗口切换与晚到保存核验要覆盖。

## 6. 产品边界与取舍

避免第一版就加入整套规则编程、UDIM/序列帧导出器、批量重命名、云协作、全局文件索引。专业贴图命名可以后续以小型专用方案增加：贴图通道、分辨率、UDIM 是字段，不自动操作导出器。

“学会用户习惯”先落实为可解释的本地固定项和作用域内最近值。只有用户明确采用建议，才把它变成规则；不依赖后台 AI 推测用户正在做什么。

## 7. 我建议的最终落地次序

| 阶段 | 交付内容 | 验收任务 |
| --- | --- | --- |
| 基础闭环 | 结构化字段、就地编辑、完整名称恢复、来源与兼容配置 | 更换主体/类型不用管理页，撤销后规则完整 |
| 连续工作 | 请求绑定的成功快照、窗口草稿隔离、续存/变体动作、本次变化 | 连续保存同一文件不用重选字段；两个窗口不串名 |
| 更低门槛 | 从实例建方案、显示名/输出值映射、局部键盘流程 | 用户把一个已有规范转成可用方案，再完成一次命名 |
| 项目流程 | 交付成对方案、有限依赖、专业字段包 | 明确知道换了什么名称和位置，不误改实际格式 |

源代码落点延续 `quick-naming-next.md`。补充关注 `app_state.h` 的会话隔离、`save_session_types.h` 的请求关联与 `WM_RESULT / VerifySave` 的晚到结果处理。开发与验证遵守工作区 AGENTS 指令，不打包，不动用户应用。

## 8. 交互示意与真实实现的区别

本轮示意可操作：续存/变体/交付动作、字段选择与搜索、临时值、变更摘要、自由编辑/恢复结构、撤销/重做、两种显示。

已用本地 Chromium 检查动作结果、候选筛选、撤销/重做、目录与命名回退的区别、自由编辑恢复、片段点击、非法字符提示、两种显示共用状态、60 字主体以及 320/400/736 像素宽度的横向溢出；检查通过。字段面板与名称直改的截图已人工查看。宿主提供的轮播控件未在此浏览器检查中模拟，检查直接切换两种显示的可见性。

名称、目录和版本数据均为内置示例；不会读取磁盘、写回应用或保存文件。“从实例建方案”、真实编号复核、输入法适配、跨窗口隔离、跨软件字段复用属于后续原生实现范围，不能把示意运行成功视为已经完成它们。

## 最终选择

默认保留清楚的字段面板，以“连续工作”作为下一阶段的重点。让用户看到自己正在延续什么、这次具体改变什么，同时始终留有恢复入口。这比增加更多命名选项更能改善每天的使用体验。
