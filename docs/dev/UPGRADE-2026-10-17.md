## SD Save Image 触发修复

实际复现并修复了空文件名导致保存按钮禁用、从而整个通用窗口被排除的问题。窗口发现现在接受禁用但可见的保存按钮，提交仍要求唯一、启用且可调用。增加同进程模态窗口发现，不再要求它的标题一定以 Save / Export 开头；新增 Ctrl+Alt+J 主动重新检测。继续排除密码框、只读、歧义候选，不将打开窗口当作保存。

Qt 标准 QFileDialog 使用框架对象路径识别目录、文件名和格式；空文件名时从单一扩展名筛选器读取后缀，后缀改变也会让旧写入请求失效。本机 SD 15.0.0 实际 Save Image 已验证自动出现、目录与 PNG 后缀、标签回填；恢复了原空文件名，没有保存或关闭用户图像窗口。

最终构建通过隐藏检查、通用前台回归、原生窗口回归，以及使用 SD 自带 PySide6/Qt 运行库的三个专门窗口检查。结果见 `tests/output/qt-save/verification-summary.json`。测试没有安装 SD 插件或修改其工程；开发预设保留，访问真实 SD 文件夹会正常增加历史，dist 未更新。改动前源码备份在 `build/save-window-backup-20261017-194903`。

边界：没有任何保存窗口且直接写盘的动作没有统一的 Windows“保存前”事件。完全不暴露控件的软件仍需对应应用接口；本次没有宣称通用拦截任意文件写入。


## 通用快速跳转（系统窗口 + Qt 标准文件窗口）

Qt 标准 QFileDialog 现显示完整快捷位置和路径输入，与现有系统窗口共用 UI。导航能力根据 filename / lookIn / fileType 等框架控件结构及调用能力确认，不按软件名特判。只有存在的目录才能发起导航，末尾路径分隔符及第二次目录属性核验避免把路径当作待保存文件；导航后从独立路径栏确认目的地、恢复名称并检查格式。Qt 会把导航时的 Save 按钮改成 Open，代码核对的是同一个元素身份。不会把任意 Open 按钮当成导航按钮。

空名称跳转、中文和空格目录、收藏跳转、手动路径、目标目录版本重算、实际为文件的路径拒绝、不存在目录拒绝、原格式保留、导航不接受保存，均已用 SD 自带 Qt 运行库的真实 QFileDialog 验证；任意标题模态保存窗口同样通过。尚未在 SD 真实 Save Image 上单独重跑本轮目录切换，前一轮的真实 SD 自动出现和回填验证仍有效。

另修复路径编辑在异步编号期间提前重新打开而被失焦消息取消的问题，并在导航成功后清理路径编辑状态。隐藏检查、通用接入、原生窗口与完整工作流回归通过。配置保留，dist 未更新；源码备份 `build/navigation-backup-20261017-200635`。

范围边界：当前可自动导航系统窗口与标准 Qt 文件窗口，其他已接入框架仍使用原有专用能力。未实现任意路径栏手动绑定，未保证未知自绘窗口导航，也未做坐标模拟或进程注入。

## WPS 与自定义面包屑地址栏

增加了独立于标准 QFileDialog 的地址栏导航。按“此电脑 / This PC”面包屑结构和唯一编辑入口识别，不按软件名或固定坐标操作；支持 InvokePattern 及旧版辅助功能的默认动作。点击快捷位置后，在前台 UI 线程切回目标窗口，后台核验地址栏位置、可写能力、实际焦点及现有目录，再发送地址栏 Enter。跳转后重新展开已重建的地址栏，回读实际目录，并验证原文件名保留。不会调用 Save，也不会创建目录。

确认的目录只在当前窗口会话、同一面包屑元素身份及内容下复用，不从“桌面”等本地化标题拼接路径。“此电脑”没有真实目录，仍可选择快捷位置；选中真实目录后才能计算自动编号。未取得路径时提示“选择快捷位置或输入目录”。

真实 WPS Office 12.1.0.28505 的“文字文稿1→另存为”已验证图片快捷位置、从“此电脑”跳入真实目录、手动路径返回桌面，原名与 Microsoft Word 格式保留；未提交文档保存。独立宿主覆盖地址回显但实际未跳转、无效路径、文件路径、多个地址栏、重复导航、中文空格路径及零保存提交。测试绑定自建进程 PID 或本工作区测试宿主路径，避免用户仍打开保存窗口时串入。

改动前源码及开发配置备份：`build/wps-navigation-backup-20261017-202523`。开发配置保留，正常访问目录会更新历史；未打包或修改 dist。最终测试报告在 `tests/output/breadcrumb`。未知自绘窗口仍需符合已验证的控件协议，不能承诺所有软件无条件可导航。
