# 快速命名下一步：推荐方案

> 历史设计文档：旧标签与分组系统已于 2026-10-19 删除，当前操作与检查以 README 和交付说明为准。

日期：2026-10-18。本文是产品与实现提案，依据当前源码和文档分析；未修改运行中的程序，也未进行新一轮实机测试。

后续实现与测试已完成，实际交付范围见 [交付说明](quick-naming-delivery.md)。本文保留为原始提案。

推荐把快速命名升级为「有字段含义的命名面板」：方案负责结构，字段负责内容，用户只修改本次变化的部分。保留自由标签组合，给频繁重复的保存工作增加结构化模式。

## 1. 目前真正值得改善的地方

现有能力已经包含多标签、前后缀、阶段、日期、变量模板、后台编号、方案、项目、组合撤销与重做、保存核验。这些应复用，不应再次作为新增功能。

从实现可以确定的几个问题：

| 现状 | 对操作的影响 | 推荐改变 |
| --- | --- | --- |
| 普通标签按点击顺序拼接，只有文字值，没有字段身份 | 点选顺序影响文件名；同类内容可以叠加 | 可选的结构化字段，顺序由方案定义，同字段互相替换 |
| 标签分组下拉显示为“命名方案”，另外还有“保存方案”和“组合模板” | 不容易知道哪个入口管内容，哪个入口管结构或目录 | 明确区分“标签库”和“方案”；模板编辑收进方案设置 |
| 模板已经能可视化配置，但入口主要在管理流程 | 经常变化的变量仍需要离开主面板编辑 | 套用方案后，在主面板显示它的字段值 |
| 直接编辑最终文件名会清除字段、智能命名及组合历史 | 改一个字可能失去整套结构和回退路径 | 优先编辑字段；修改完整名称成为明确、可回退的自由编辑操作 |
| 主界面常用区取分组中前六个 pinned 项 | 固定位置很好，但内容多时频繁进入搜索 | 保留固定顺序，在当前字段的候选面板补充搜索与最近值 |
| 版本/序号已有后台计算和保存前复核 | 能力完整，但常用时入口和计算依据还可更清楚 | 常用方案直接露出版本字段，显示计算中、候选值和复核状态 |

来源：`src/main.cpp` 的 `toggleNameField`、`perform`、主面板构建、`ID_PREVIEW / EN_CHANGE`、`buildTemplateManager`；`src/model.h` 的 `Preset / Recipe / SmartNaming`；`src/model.cpp` 的 `smartNamingPreview / chooseGroup`；`src/workflow_ui.h`；`src/naming_session.h`。

这些是代码行为分析，不是用户操作耗时的实测结论。

## 2. 核心体验：一次配置，以后只改变化项

以“海港”项目的角色工作文件为例：

`海港_守卫_模型_工作_v012.blend`

方案定义顺序：项目 → 主体 → 类型 → 阶段 → 可选日期 → 版本。格式仍来自原软件。

- 点“守卫”可以换成“哨塔”，其他字段保持；当前编号按新主体重新计算。
- 点“模型”换成“材质”，替换同一个位置，不追加为“模型_材质”。
- 点“工作”换成“交付”，只改阶段。只有明确选择了带目录的保存方案，才切换目录。
- 新内容可在字段候选面板直接输入，默认仅用于这一次；“加入标签库”是独立操作。
- 没填写的可选字段不留下多余下划线；必填字段缺失时定位到该字段。
- 新旧候选值切换，支持组合撤销和重做。

真正的收益是减少用户对点击顺序、清理重复词和重新输入固定部分的记忆负担。

## 3. 主面板怎么改

继续使用现有紧凑侧边/底部面板，不增加常驻的大型设置区。

1. 上方保留位置区。项目与当前方案使用轻量入口，可见当前上下文。
2. 命名区在“自由组合”和已配置的结构化方案之间选择。现有用户仍可按原习惯使用自由组合。
3. 结构化方案使用现有两行三列区域显示最多六个常用字段卡片，卡片同时显示字段名和值。更多字段按需展开。
4. 点击字段打开就地候选面板：固定常用、少量最近、搜索、临时输入。一次只展开一个字段。
5. 下方持续显示完整名称与原软件格式。较长名称可展开查看全文，不能只依靠悬停才能核对。
6. 仅把当前方案常用的版本、阶段等信息直接露出；前后缀和替换仍按需展开。
7. 命名区提供可见的组合撤销入口。“还原初始名称和位置”继续是独立动作，避免两种回退含义混淆。

字段编辑期间不重新排列候选按钮，不因推荐刷新而改变鼠标下的目标。固定常用项始终保持用户顺序。

## 4. 第一优先级：字段、结构和编辑连续性

### 字段不是另一套字符串标签

每个字段至少需要：稳定 ID、显示名、单选/多选、必填性、候选来源、默认值、当前会话值；方案保存字段顺序和分隔符。结构化字段默认单选，备注类字段可以显式启用多选。

候选条目也需要稳定 ID。当前 `nameFields` 通过文字值识别选择，未来不能让不同字段里的相同文字互相取消，也不能因修改显示名而丢失选择。

旧标签导入后仍是自由组合内容，不自动猜测“角色”“类型”等类别。用户可把一个旧分组复制成结构化方案，再逐步指定字段。

### “改一个字”不能让整套命名失效

主路径是点击字段直接改值，保留日期、版本、前后缀等规则。

编辑完整文件名时，建立完整结构快照，明显显示当前已进入自由编辑；允许撤销回原结构。不要尝试把任意手工字符串强行反向拆成字段。

在文字输入框内保留原生 Ctrl+Z；组合撤销使用单独入口，不能夺走文字编辑的撤销行为。一次字段编辑从获得焦点到提交作为一个组合操作，不能逐字产生几十条组合历史。

原软件直接改名时，继续以外部真实输入为准并废弃旧异步结果；允许显式恢复上一结构，但不能自动覆盖外部修改。

### 处理顺序必须明确

结构化方案建议统一为：解析字段来源 → 按方案顺序组装 → 应用前后缀/修饰 → 应用替换规则 → 计算编号 → 校验最终结果 → 回填名称主体。

旧方案保留原有求值顺序和输出，新增方案用版本化配置明确新行为；不得在升级时悄悄改变旧名称。结构化方案中的日期/阶段是唯一来源，相应旧工具操作同一字段，避免双重追加。

可选字段省略时只消除其结构分隔符，不清洗用户值内部有意义的下划线。扩展名始终由已核验的原软件格式单独处理。

## 5. 第二优先级：就地候选和有边界的上下文记忆

候选优先级建议为：用户固定项 → 当前项目/字段最近使用 → 字段其他候选。搜索优先精确匹配和前缀，再匹配名称与现有关键词。拼音/首字母可以后续增加，无需成为首版依赖。

保留现有程序和目录关联逻辑。字段最近值按项目与方案隔离，避免做完 A 项目后把资产名带入 B 项目。

默认只记住方案、固定选项和候选历史；资产主体在新会话中作为候选提供，不自动覆盖原软件名称。项目前缀、作者等固定值可以在方案中明确设为继承。

自动关联先用于建议合适方案；用户显式选择或配置“自动套用”后才应用。已开始编辑的会话，不因目录或推荐变化而偷偷更换方案。

项目继续由用户明确选择。不同项目可能使用同一个程序、共享导出目录，仅凭程序或文件夹名字不能可靠认定项目。

“最近成功使用”基于已核验的保存记录更新；点击过但取消的值最多属于当前会话候选，不能被当成成功保存来训练排序。已有仅填入能力的接入也必须可用，只是不产生未经核验的成功记录。

## 6. 第三优先级：把版本变成日常操作

复用现有后台版本计算、过期任务丢弃和提交前复核。

- 在常用工作方案直接显示版本值，点击可切换自动版本、自动序号或手动值；首版继续保持版本与序号互斥。
- 候选计算期间显示“计算中”；旧号码不能被当作新名称已经就绪。
- 预览和撤销不消耗编号；取消保存也不消耗编号。
- 改主体、目录或格式时重算。切换阶段默认按最终名称各自编号，阶段之间统一递增仅作为后续显式选项。
- 默认保留当前“同目录、同名称根、同扩展名”的编号范围，并在详细信息里说明依据。
- 复核发现 v012 已占用时继续沿用现有旧/新名称确认，不静默提交另一个版本。
- 从原软件直接保存不保证走 Jump 的提交前复核，原软件覆盖确认始终保留。

后续可增加“沿用上次结构并保存新版本”：先恢复结构，仍按当前目录、原软件格式重新计算。它不能被包装成任意软件都能无窗口增量保存。

## 7. 最值得拓展的三个方向

**A. 工作/交付成对方案。** 同一套资产字段，提供工作与交付两个方案。可以绑定项目现有相对位置；先明确展示将切换的目录再执行。仅改阶段不自动换位置。工作文件 .blend 和交付文件 .fbx 的真实格式依然在原软件选择，不能靠改文件名后缀冒充导出。

**B. 从现有名称提取字段。** 仅对当前明确选中的模板做精确匹配，预览拆分结果；有歧义时保留原名。先支持自身生成的名称，不先做全能识别器。

**C. 一次性的命名规范检查。** 方案可声明必填字段、编号位数、允许的字段值等。问题落在具体字段旁，点击即可修正。默认只在使用该方案时执行，不把自由命名变成强制规范。

暂不优先：AI 猜文件内容、批量重命名磁盘文件、云同步和协作、独立资产管理、无窗口全局保存拦截。这些会明显扩大复杂度，对当前高频保存动作的收益不如字段编辑直接。

## 8. 实施顺序与验收

按可独立验收的增量推进，不一次重写整个 UI。

### 第一批：形成完整的结构化命名闭环

- 增加结构化方案字段模型与兼容加载；现有方案、标签库、颜色、关键词、排序保持。
- 提供一个“资产工作文件”示例，用户可复制编辑。
- 主面板字段替换、临时输入、空字段处理、最终预览、组合撤销。
- 完整名称自由编辑有状态提示和恢复结构入口。
- 已有自动编号、回填、格式边界沿用。

验收：同字段替换只需一次候选选择，不产生叠加；不同点击顺序得到相同结构；改主体不丢阶段和编号规则；临时值不污染预设；撤销恢复结构并重算编号；原软件手工改名不被旧任务覆盖。

### 第二批：降低找内容的成本

- 在字段候选面板接入现有搜索能力。
- 项目/方案隔离的最近候选与稳定固定区。
- 清晰命名标签库、方案及模板设置入口。
- 高频版本信息就地显示。

验收：已配置方案中更换主体不进入管理窗口；固定项位置不随使用频率变化；取消保存不计入成功记录；切换项目不会自动套入上一项目资产名。

### 第三批：按实际使用需求扩展

- 工作/交付成对方案。
- 当前模板的精确名称拆分。
- 方案级规范检查。

先用一个真实项目验证第一、二批，观察是否减少打开管理页和清理名称的次数，再决定第三批投入。本文不提供未经测量的提效百分比。

## 9. 代码落点与验证范围

- `src/model.h / model.cpp`：稳定字段标识、方案结构、兼容配置、纯命名求值；避免让窗口事件承担新增拼接逻辑。
- `src/naming_session.h`：快照加入结构化字段与自由编辑模式；建立明确的撤销边界。
- `src/main.cpp / workflow_ui.h`：主面板字段、候选选择和方案编辑入口；沿用现有输入框及弹窗交互。
- `src/naming_worker.h`：复用异步计算框架，缓存/过期判断纳入结构、字段值、项目、目录、格式与规则变化。
- 新字段功能补充实际语义测试：同类替换、同文字不同字段、可选字段、临时值、编辑恢复、配置往返和旧方案输出一致。
- 涉及组合/编号运行现有 `workflow_integration.py`；涉及主面板布局运行 `layout_smoke.py`；涉及新增候选焦点再选择对应交互检查。
- 若回填通路变化，再运行 `native_integration.py` 和 `generic_integration.py`；未触及的接入不无理由重测全部真实软件。
- 布局检查至少覆盖 100%、125%、150% 缩放与侧边/底部布局，关注中文长名称、候选展开、键盘焦点和输入法候选。

开发继续使用 `dev.ps1 / Start-Test.cmd` 和独立测试宿主，保留 `build/dev/settings.ini`。未经便携发布请求不打包，不覆盖 `dist`，不关闭用户应用或保存窗口。

## 决策

下一版最值得做的是：**结构化字段 + 就地替换/输入 + 可恢复的编辑 + 常用版本操作**。把已有能力串成每次保存时自然可用的一条操作路径，优先让一个真实项目用得顺，再扩展更多自动化。
