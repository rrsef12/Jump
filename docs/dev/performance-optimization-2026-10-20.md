# Jump 性能优化结果 · 2026-10-20

已完成共享方案缓存、配置读取、自动记录保存和方案编辑器初始化优化。当前配置的方案编辑器由约 468 ms 降到 76 ms；100 个方案的压力配置下，启动由约 3.68 s 降到 0.49 s，方案菜单由约 382 ms 降到 22 ms。

原始检查与瓶颈分析保留在 [性能检查](performance-audit-2026-10-20.md)。本次仅更新开发版，没有打包或更新 `dist`。

## 实际修改

1. **方案列表、菜单和编辑器共用解析缓存。** 所有内置和自定义方案使用同一目录与 ID 索引；根据方案内容及相关默认参数判断缓存是否失效。编辑、复制、删除、导入、恢复和失败回退后使用最新定义。最近名称等无关记录不会让方案重新解析。
2. **减少启动时的重复配置读取。** Windows INI API 每个 section 读取一次，缓存本次加载的键值；保留 Windows 的编码与整数兼容行为。十六进制编码、解码使用预分配缓冲区；没有旧数据迁移时，跳过仅为迁移所需的方案解析。
3. **高频自动记录合并后在后台保存。** 最近名称、最近目录使用单一写入线程，180 ms 合并窗口仅保留最新待写快照；正在写入的旧快照完成后才写新快照。保留备份、原子替换、可靠落盘、失败反馈和重试。正常退出时等待必要落盘，手动备份和导入前也会同步等待。
4. **编辑器按需创建控件。** 简易视图只创建实际字段所需的控件；“更多规则”的四个页面分别在首次访问时创建，之后复用。模板使用共享缓存，候选列表批量填充，布局和文字更新减少重复绘制。草稿、取消和保存语义保持一致。

显式点击“保存方案”或“保存常规设置”仍等待写入结果，以便准确反馈失败并执行回退。自动记录已移出界面线程，不能据此认为所有保存都不会受磁盘或外部文件锁影响。

## 测量边界

- 本机 i5-13600KF、20 个逻辑处理器、32 GB 内存；数值代表本机 Debug 版本，不代表 Release 或其他电脑。
- 当前配置含 4 条已保存方案／流程；压力配置含 100 个自定义方案和 100 个项目，每方案 8 个字段，其中 5 个字段各 20 个候选，配置约 2.5 MB。
- 压力场景编辑器打开的方案本身也更复杂，当前／压力差异同时包含字段和候选数量的影响。
- 启动为已有文件缓存时的进程启动，非开机冷启动；窗口与控件耗时不含显示器最终呈现。
- 最终多数动作采样 3–5 次、方案编辑器 7 次、规则页切换 15 次，重复窗口检查精简为 3 轮；优化前编辑器与窗口重复检查样本更多。中位数适合观察主要变化，不能由本轮最大值推断罕见卡顿上限。
- 显式保存仍可能出现磁盘、权限或共享冲突导致的等待，中间采样曾出现数百毫秒波动；本次最终采样未出现不代表此类波动已消失。
