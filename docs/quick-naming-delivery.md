## 直接开始

运行 `D:\Code\Jump\Start-Test.cmd`。命名区只保留方案信息、常用字段和最终名称，通过右上角“命名设置”统一切换方案、编辑规则或展开全部字段。游戏引擎资产、贴图资源、项目分类与编号均有示例；复制后修改字段、候选和输出设置即可适配项目规范。

快捷点选按方案生成，“命名设置 → 本次命名 → 显示全部字段”展开其他有效字段，再点取消勾选返回。点击值才出现临时输入框；Enter 保留并收起，Esc 撤回。右键候选改名会立即持久化到当前命名方案，方案默认值与本次资产名分开。组合撤销和重做在“撤销与还原”中，编号在“本次命名”中直接选择。

附加字段编辑器保留点击展开、Enter 收起、Esc 撤回的交互。两种界面均无需“使用”，修改直接更新预览及原窗口名称。输入期间不会因名称长度变化重建控件；无效内容及中文组字期间不发起名称填入或保存。

测试中出现过一次配置替换失败，复跑恢复；进一步通过持有读取句柄的确定性检查复现其冲突条件，加入了有界重试。大结构测试还揭示了 Windows 配置节截断问题，已改为分段保存并验证完整读回。

## 明确的边界

这版聚焦单文件保存时的命名。字段为单值，每个字段支持一条等值出现条件；没有任意逻辑表达式、批量重命名、云同步或引擎导出器。现有名称拆分后仍需用户确认字段含义。

版本号按目标目录已有文件计算；不会把示例名称里的数字直接当作已占用版本。保存前复核不替代原软件的覆盖确认，也不可能锁住其他程序随后创建同名文件的行为。

结构恢复来自本机最多 50 条已核验保存记录；只有精确匹配软件、项目和实际路径才恢复。会话草稿只覆盖仍然打开的窗口。新窗口默认沿用当前文件自身的名称，不猜测另一份资产的主体。

输入法检查覆盖组合开始、确认和结束消息；不同输入法和真实第三方软件的全部交互仍需在日常使用中观察。没有将测试宿主的通过等同于所有软件均兼容。
