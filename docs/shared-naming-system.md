# 命名方案的共用系统

方案是同一套字段命名系统的参数集合。新增或修复交互，应修改共用实现，不按方案 ID 或字段 ID 分别实现。

## 数据与界面约定

- `namingSchemeCatalog` 是面板切换、设置中心列表、编辑器示例及新保存窗口的统一方案目录：按方案身份合并已保存定义和全部内置默认，已保存定义优先。“资产文件”同样可以原位编辑；仅主动复制或选择其他示例时创建新身份。查看和取消不会写配置，内置方案修改后可还原默认。
- 输出顺序由 `StructuredNaming.fields` 决定；界面通过 `namingDisplayOrder` 将 `primaryField` 放在前面，再展示常用字段和其他字段，不改变输出顺序。主字段可以使用任意 ID、任意存储位置。
- 常用视图显示常用字段、主字段及需要修正的字段；条件隐藏的字段不参与输出或校验。固定文字只展示，在方案编辑器中修改。
- 字段来源、默认值、候选、条件、校验、连接符、前后缀、大小写及补零均为方案参数。资产方案的旧阶段库只在创建模板时合并为候选数据，复制后的方案也不需要特殊分支。
- 编辑器每项都有常驻“设置”，主要名称、自动来源和固定文字均可直接编辑；行下方展示实际启用、必填、输入限制与格式规则，停留显示完整说明。下方“方案功能设置”统一控制整个文件名的格式、目录推荐、同名检查及关联软件。“＋ 添加”保留新增、编辑已有内容、文件名格式、目录推荐、关联软件与复制；编辑已有内容和行内设置进入同一编辑器，含基本设置、输入与格式、候选与条件三页。“自动带入原文件名”直接修改共用的 `primaryField`，每个方案最多指定一个字段；项目、日期和固定文字来源不能接收原名。页面导航允许保留未完成的规则以便修正，最终保存仍完整校验；所有入口使用同一份草稿，满 8 字段仍能调整已有规则和软件关联。
- 默认字段使用“项目名称、主要名称、文件类别、补充说明、当前状态、日期”。共用反序列化入口按字段身份与旧默认名称一起迁移，覆盖已有方案副本及保存记录，保留自定义名称、字段值、条件和顺序；查看不写配置。左侧列表只显示序号与字段名称，原文件名接收与主面板显示在右侧用完整设置项说明。
- 左侧按真实拼接顺序排列字段；预览使用同一命名引擎显示名称组成、当前字段片段及条件隐藏或空值未输出的原因，不维护另一套拼接规则。
- 所有可编辑文字字段共用同一种组合框外观。候选不足三项时保留可更新的控件位置；新选中的自定义值可以就地成为可见候选。没有候选的文字字段不生成虚假候选行。
- `StructuredNaming.locations` 保存最多 20 条“字段、实际输出文字、目录”规则。JNS2 顶层元数据按需增加第 4 项目录规则，第 5 项 `recommendLocations` / `warnExisting` 功能开关；默认开启且无规则时仍用原 3 项。字段元数据按需增加第 14 项 `enabled`，旧数据默认启用。方案保存、复制、导入导出及文件保存记录共用该序列化。候选改名同步引用的输出值，删除字段清理对应规则。
- 字段限制同样应用于声明候选、保存历史和最近名称。方案切换带入的名称不符合新规则时，原值保留，就近显示原因；最终文件名标明保留的是上次有效结果，修正后继续回填。

## 共用操作

- 全局与软件默认均保存方案 ID，并由 `defaultNamingScheme` 从共用目录解析；软件使用小写可执行文件名匹配，优先级为有效软件默认、有效全局默认、资产文件。`activeNamingScheme` 仅记录临时选择，旧配置首次加载时将其迁移成全局默认。已有窗口草稿和已保存文件记录优先恢复；设置默认不改当前草稿，内置规则还原保留默认绑定，自定义方案删除清理引用。两处默认菜单共用 `naming_defaults_ui.h`。
- 两种方案编辑视图共用“新增命名内容”：主要名称、项目名称、日期、文件类别、补充说明、当前状态、手动编号、固定文字及自定义内容都转换成已有 `NamingField` / `primaryField` 参数，不扩展命名引擎或引入方案分支。新增主要名称沿用原名，新增项目与日期自动带入。`designerContentPresets` 从共用默认字段取常用候选，手动编号只设置数字校验、默认 1 和三位补零，不改变方案自动编号。`designerExistingContent` 优先按原名映射、自动来源或常用项名称识别已有内容，再按主要名称、项目名称与日期的名称兼容旧方案；点击进入已有字段编辑，保留其来源和规则，避免重复添加。固定文字与自定义允许多个。8 个字段的限制仅禁用确实新增的命名内容，已有内容仍可编辑，添加入口保持可用。
- “＋ 添加”的全部菜单项通过共用 `PopupMenuHint` / `trackPopupMenuWithHelp` 提供 450ms 停留说明，覆盖顶层、子菜单、已有字段和满额禁用项。内容说明从当前草稿的实际来源、必填与候选数量生成，不按方案身份分支。说明避开已打开的菜单并限制在屏幕工作区内，切换选项、移到分隔线或退出菜单会取消待显示任务并隐藏；键盘导航沿用同一说明。菜单关闭时销毁说明窗口和定时器，不影响原有点击及长名称完整提示。
- “＋ 添加 → 关联软件”按需显示同一份软件默认映射，不在字段结构中另存规则，不参与拼接，不占字段名额。已有绑定打开时自动显示；每方案一个关联项、内部多个 exe；菜单显示数量，已存在时点击定位到同一区域。删除此项清空关联草稿，保存后解除全部绑定；未保存时取消可恢复。布局收放保留当前输入，各示例独立保留关联项的显隐与草稿。`namingSchemeApplications` 读取当前方案关联；`setNamingSchemeApplications` 校验并替换该方案的关联，保留其他方案的软件，重绑同一 exe 时统一更新。软件关联与方案定义通过 `storeNamingScheme` 一次保存，失败整体回退；新建、编辑、两种视图与切换示例均使用草稿，取消不写入，复制方案不继承关联。新保存窗口仍由 `defaultNamingScheme` 统一选择。
- `selectStructuredField` 负责两个视图的输入会话；`liveStructuredInput` 处理输入、输入法和校验；`applyStructuredValue` 统一处理快捷候选、全部字段候选、最近名称和来源恢复。
- 候选在两个视图和下拉菜单中均支持再次点击取消。`NamingField.omitted` 表示用户明确从本次文件名中排除该字段，输出、条件和就地校验共用此状态，撤销和已保存文件可恢复它。方案的必填约束与默认值保持不变；新会话及保存方案定义时清除临时排除状态。必填主字段和固定文字仍不可取消。
- `NamingField.enabled` 是独立的方案级整项开关，与本次取消的 `omitted`、主面板显隐的 `quick` 分开。共用 `namingFieldVisible` 同时负责关闭字段、依赖条件、两个主面板、预览、目录推荐和校验；关闭时保留全部规则，恢复时继续使用。禁用字段可暂存不符合自身字符限制的默认值，Windows 文件名基本合法性仍校验。输入限制选 0 可关闭额外字符限制，补零选 0 独立关闭数字要求；“关闭本页规则”将大小写、限制、补零、连接符、前后文字统一恢复默认，不改其他页。
- 候选按钮的快速第二次按下在共用控件层按普通按下处理，释放时完成一次切换，避免 Windows 的双击通知被单击处理器漏掉。两个视图共用此行为；位置按钮保留双击保存，候选始终只修改命名。
- 两种视图均可访问按项目保存的最近名称。撤销、重做、编号、修饰规则、整名编辑和原窗口回填继续共用原有保存链路。
- “预览多个文件名”使用当前未保存草稿，复用 `namingSession`、`composeStructure` 和编号格式函数；每行一个示例，左侧输入、右侧原名与新名对照，首次带入示例，支持清空与恢复示例。`namingTrialPreview` 一次生成结果、错误与逐项解释，列表及选中项的可折叠说明共用同一结果。空值解释合并，条件隐藏与错误使用具体修改提示；清空后再打开保留空白。最多显示 20 项，超出明确提示；不修改真实保存窗口或配置、不访问目录，编号仅作格式示例。
- `namingRecommendedLocations` 只匹配可见、有效且未取消字段的实际输出，项目内路径通过 `projectPath` 解析，无项目时跳过相对目录；匹配本身不做文件系统访问。主面板和位置列表共用此结果，按路径去重。点击推荐复用原目录导航和编号链路，不自动创建目录或保存文件。
- 同名检查在名称、目录或窗口变化后合并 220ms，通过有界后台线程仅读取精确目标的文件属性；不扫描目录、不读取内容、不空闲轮询。请求序号、窗口 generation 和当前目标路径共同排除过期结果，失败明确提示。提示展示检查时的修改时间及大小，操作复用共用编号、改名与目录打开；外部写入后可手动重新检查，实际覆盖确认仍由原软件负责。最终文件名、同名提示及底部状态按固定顺序定位，长名称换行时同步调整。
- 从原窗口手动改名后，首次字段编辑会保留完整的原始结构；Esc 恢复手动名称，不重新附加默认字段，也不留下可复活的临时撤销状态。
- 切换项目通过方案默认值重新建立会话，清空原名映射字段，重新读取继承项目和动态日期，不再依赖 `subject` / `variant` 等特定字段名。
- 交付操作只使用方案中已有、显示名或输出值为“交付”的有效候选；没有该选项时沿用当前命名，只切换目录。不添加字段或改变编号方式。
- 方案 ID 的特殊识别仅用于模板定义、旧格式迁移及内置方案身份管理。

## 本次验证

完整功能控制的定向回归为 `python -X utf8 tests/naming_designer_integration.py --controls-only`：共用模型兼容旧序列化及新开关，逐一核对各内置方案的设置入口；覆盖预览错误定位、关闭输入限制、清除格式、无效默认值下仍可进入修正页、整项关闭与恢复、目录规则关闭后保留、同名检查独立开关、取消不落盘、保存重启恢复以及实际主面板生效，不提交保存文件。

文件名效果预览的定向回归为 `python -X utf8 tests/naming_designer_integration.py --preview-only`，只覆盖改名前后对照即时更新、错误提示、按选中项展开说明、示例与清空、空状态、20 项限制及重开后的输入保留，并确认方案、原保存框名称与配置均未改变。

本轮三个扩展的定向回归为 `python -X utf8 tests/naming_designer_integration.py --assist-only`：先运行共用模型检查，再通过自有真实保存窗口覆盖多名称即时预览、条件与错误说明、目录规则取消及保存恢复、推荐目录导航、按目标目录重算编号、同名元数据、长名称下提示与状态不重叠、换号以及原窗口实际保存；使用独立配置，不覆盖已有文件。

默认方案的定向回归为 `python -X utf8 tests/default_schemes_integration.py`：仅操作两个自有测试宿主，覆盖管理页与面板两个入口、两个程序默认的隔离、重启、恢复跟随全局、默认修改不改当前草稿、自定义方案删除后的回退。INI 往返、旧配置迁移、大小写与安装路径变化、缺失方案回退及改名不丢失引用由模型检查覆盖。

统一添加与编辑页软件关联的定向回归为 `python -X utf8 tests/default_schemes_integration.py --designer-only`：覆盖常用项添加与已有项不重复、满额继续编辑、文件类别和状态候选保存、手动编号补零及来源保存，满 8 字段仍可添加软件、布局收放保留输入；在真实 exe 选择框中添加两个自有宿主，覆盖多软件、去重、两视图与示例草稿、取消、保存、复制隔离、重新关联提示、单个移除或整项删除后的回退，以及新建方案首次保存后自动选择。使用独立配置并检查开发配置未变。

`scheme_system_integration.py` 用同一组行为检查资产文件、游戏引擎资产、贴图资源、项目分类与编号，以及主字段不叫 subject、位置不同且未标记常用的自定义方案。另覆盖固定文字、条件、数字补零、项目与日期来源、无效继承值、手动名称取消和交付操作。

候选取消的定向回归可运行 `python -X utf8 tests/scheme_system_integration.py --toggles-only`，覆盖上述五种方案的两个视图、下拉、撤销重做、条件字段及真实保存重开，避免为单一交互重跑无关检查。

快速连点的定向回归为 `python -X utf8 tests/quick_picks_integration.py --rapid-only`：真实鼠标连续点击、300 ms 回填延迟、不同字段交替添加／取消、两个视图及其他方案，检查选中状态与最终原保存框文件名一致，且不提交保存。

方案目录的定向回归可运行 `python -X utf8 tests/naming_designer_integration.py --catalog-only`，覆盖内置方案可见性、资产原位编辑、两个入口读取一致、取消无写入、保存重启、复制隔离及还原默认。

添加菜单中规则的定向回归可运行 `python -X utf8 tests/naming_designer_integration.py --rules-only`，通过真实菜单检查唯一已有内容列表、三种字段规则与文件名格式、返回填写与旧入口隐藏；覆盖原名映射、预览组成和条件隐藏、排序、输出格式校验、草稿取消及保存重启。

字段名称的定向回归可运行 `python -X utf8 tests/naming_designer_integration.py --labels-only`，只检查四个内置方案、旧副本名称更新、自定义名称保留、取消无写入、保存重启及文件名输出保持一致。

相关现有检查为 `naming_designer_integration.py` 和 `quick_picks_integration.py`，覆盖方案编辑、复制、重排、持久化，以及资产基线的输入法、实际鼠标操作、撤销和真实保存。正常迭代继续使用 `dev.ps1`，保留 `build/dev/settings.ini`，不打包 `dist`。
